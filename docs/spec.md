# dummy_data_gen 使い方ガイド

このツールを初めて使う方向けに、専門的なプログラミング用語をできるだけ使わずに説明した資料です。

---

## 1. このツールは何をするもの?

**dummy_data_gen** は、名前・メールアドレス・住所などの「見た目はそれらしいけれど、実在しない架空のデータ」を、指定した件数だけ自動で作ってくれるツールです。

### なぜ必要なのか

システムやレポートツール(Dr.Sum、MotionBoard、Datalizer など)の動作確認をするとき、本物のお客様の個人情報を使うわけにはいきません。かといって、テストのたびに手作業でデータを何百件も作るのは大変です。

このツールを使えば、

- 本物そっくりだけれど**完全に架空**のデータを
- **一瞬で、大量に**作ることができ
- しかも**インターネットに一切つながずに**動くので、情報が外部に漏れる心配がありません

パソコン(Windows)の中だけで完結する、社内利用に適したデータ作成ツールです。

---

## 2. 何ができる?(できることリスト)

- 氏名・メールアドレス・住所・電話番号・生年月日・会社名など、日本語としてもっともらしいデータを自動生成できる
- 作るデータの件数や、どんな項目(列)をどんな順番で並べるかを自由に決められる
- 完成したデータは、用途に合わせて次の4つの形式で受け取れる
  - **CSV**: 表計算ソフト(Excel等)で開けるテキスト形式(既定の形式)
  - **Excel(xlsx)**: そのままExcelで開けるファイル
  - **SQL**: データベースにそのまま登録できる命令文(`INSERT INTO`文)
  - **JSON**: システム間でデータをやり取りするときによく使われる形式
- 一部の項目だけ、わざと「空欄(未入力)」を混ぜることができる(空欄が混ざったデータでの動作確認用)
- 「選択肢の中からランダムに選ぶ」項目を作れる(例: 会員ステータスを「利用中」「休止中」「退会済み」からランダムに割り当てる)
- 項目によっては「重複しない値にする」設定ができる(例: 年齢を重複なしで割り振る)
- 都道府県と市区町村をセットで作ると、「東京都なのに市区町村は北海道」のようなおかしな組み合わせにならないよう自動で対応させる
- 同じ設定と同じ「合言葉(のような数字、seed)」を使えば、**何度実行してもまったく同じデータ**を再現できる(テストのやり直しに便利)
- 数百万件という大量のデータでも、数秒程度で作成できる

なお、生成される氏名・住所・電話番号・会社名などは、あらかじめ用意された架空の候補からランダムに組み合わせて作られるものです。実在する個人・企業・住所・電話番号とは一切関係ありません。

## 3. 準備するもの・インストール

### 事前に必要なもの

このツールは「Rust」というプログラムの実行環境を使って動かします。パソコンに [Rust(rustup)](https://www.rust-lang.org/ja/tools/install) をインストールしてください。インストールが済んでいれば、それ以上の特別な準備は不要です。

### 実行ファイルを作る

コマンド(黒い画面、ターミナル)で、このツールのフォルダに移動してから、次のコマンドを1つ実行します。

```bash
cargo build --release
```

これで `target/release/dummy_data_gen.exe`(Windowsの場合)という実行ファイルができあがります。

---

## 4. 使い方

大まかな流れは次の3ステップです。

1. 「どんなデータを、何件作りたいか」を設定ファイル(`schema.yaml`)に書く
2. コマンドを実行する
3. 指定した形式のファイル(CSV/Excel/SQL/JSON)ができあがる

### ステップ1: 設定ファイル(schema.yaml)を書く

`schema.yaml` というファイルに、作りたいデータの内容を書きます。以下は例です。

```yaml
row_count: 20          # 作るデータの件数(この例では20件)
table_name: users      # SQL形式で出力するときに使うテーブル名
columns:
  - name: id
    type: sequence       # 1から始まる連番
  - name: name
    type: name_ja         # 日本語のランダムな氏名
  - name: email
    type: email            # メールアドレス
  - name: age
    type: integer           # 数値
    min: 18                 # 最小値
    max: 65                 # 最大値
    unique: true            # 値が重複しないようにする
  - name: status
    type: enum              # 選択肢からランダムに1つ選ぶ
    choices: [利用中, 休止中, 退会済み]
  - name: phone
    type: phone_ja           # 携帯電話番号風の文字列
    null_rate: 0.1            # 10%の確率で空欄(未入力)にする
```

項目ごとのポイント:

- `row_count`: 何件のデータを作るか(件数)
- `table_name`: SQL形式で出力する場合にだけ必要な、テーブル名の指定
- `columns`: 作りたい項目(列)を上から順に並べたリスト。各項目には次を指定する
  - `name`: 項目名(見出し)
  - `type`: どんな種類のデータにするか(詳しくは「5. 選べるデータの種類一覧」を参照)
  - `null_rate`: (任意)0.0〜1.0の数字で、その割合だけ空欄を混ぜる。例えば`0.1`なら10%が空欄になる
  - `unique`: (任意)`true`にすると、その項目の値がデータ間で重複しないようになる。使える種類は限られている(後述)

### ステップ2: コマンドを実行する

```bash
cargo run -- --config schema.yaml --format csv --encoding utf8
```

これだけで、既定では `output.csv` というファイルが作られます(形式によって `output.sql` / `output.json` / `output.xlsx` になります)。保存先を自分で決めたい場合は `--output` で指定します。

### 実行時に指定できるオプション

| オプション | 説明 | 何も指定しなかった場合 |
|---|---|---|
| `--config <ファイルパス>` | 設定ファイル(schema.yaml)の場所 | `schema.yaml` |
| `--format <csv\|sql\|json\|xlsx>` | 出力する形式。`sql`を選ぶ場合は`schema.yaml`に`table_name`の指定が必須 | `csv` |
| `--encoding <utf8\|sjis>` | 文字コード。日本の業務システムがShift-JIS前提のことがあるため用意されている(`xlsx`形式には効かない) | `utf8` |
| `--seed <数字>` | 同じデータを再現したいときに指定する合言葉のような数字。同じ数字なら毎回同じデータになる | 指定なし(毎回ランダムなデータ) |
| `--output <ファイルパス>` | 保存先のファイル名・場所 | 形式に応じた既定のファイル名 |

### よく使う実行パターンの例

**CSVファイルを作る(基本形)**

```bash
cargo run -- --config schema.yaml --format csv
```

**Excelファイルを作る**

```bash
cargo run -- --config schema.yaml --format xlsx --output result.xlsx
```

**データベース登録用のSQLファイルを作る**(`schema.yaml`に`table_name`が必要)

```bash
cargo run -- --config schema.yaml --format sql --output result.sql
```

**同じデータを何度でも再現する**(`--seed`に好きな数字を指定)

```bash
cargo run -- --config schema.yaml --format csv --seed 42
```

**Shift-JIS形式(日本の業務システム向け)で出力する**

```bash
cargo run -- --config schema.yaml --format csv --encoding sjis
```

## 5. 選べるデータの種類一覧

`schema.yaml` の各項目で `type` に指定できる種類と、実際にどんなデータが出るかの例です。

| 指定する種類(type) | どんなデータが出るか | 出力例 |
|---|---|---|
| `sequence` | 1から始まる連番 | `1`, `2`, `3`, ... |
| `name_ja` | 日本語のランダムな氏名 | `佐藤翔太` |
| `email` | ランダムなメールアドレス | `user123@example.com` |
| `integer` | 指定した範囲(`min`〜`max`)のランダムな整数 | `18`〜`65`の間の数字 |
| `float` | 指定した範囲のランダムな小数(`decimals`で小数点以下の桁数を指定、省略時は2桁) | `162.5` |
| `boolean` | はい/いいえ(true/false) | `true` または `false` |
| `date` | 指定した範囲(`start`〜`end`)のランダムな日付 | `1985-03-12` |
| `postal_code` | 日本の郵便番号のような形式 | `123-4567` |
| `phone_ja` | 携帯電話番号のような形式 | `090-1234-5678` |
| `address_ja` | 都道府県+市区町村を組み合わせた簡単な住所 | `東京都渋谷区` |
| `company_name_ja` | 会社名のような文字列 | `株式会社山田商事` |
| `uuid` | 世界中で重複しない長いランダムなID | `550e8400-e29b-...` |
| `prefecture_ja` | 都道府県名 | `東京都` |
| `city_ja` | 市区町村名(下記の注意点を参照) | `渋谷区` |
| `enum` | 自分で用意した選択肢(`choices`)からランダムに1つ選ぶ | `choices: [利用中, 休止中]` なら「利用中」か「休止中」 |

どの種類にも共通で `null_rate` を追加でき、指定した割合で空欄(未入力)になります。

### 都道府県と市区町村を組み合わせるときの注意

`prefecture_ja`(都道府県)の**すぐ後ろ**に`city_ja`(市区町村)を置くと、その都道府県に実際にある市区町村名が選ばれます。

```yaml
columns:
  - name: prefecture
    type: prefecture_ja
  - name: city
    type: city_ja   # ← prefectureより後ろに書く
```

順番を間違えて`city_ja`を先に書いてしまうと、都道府県との対応がとれなくなり、実行時に注意メッセージが表示されます(全国からランダムに選ばれる動作になります)。`city_ja`だけを単独で使う場合は、最初から全国の市区町村からランダムに選ばれます。

### 「重複しない値」(unique)にできる種類

`unique: true` を指定できるのは `enum` / `boolean` / `gender` / `blood_type` / `integer` / `date` / `name_ja` / `last_name_ja` / `first_name_ja` / `phone_ja` / `phone_ja_landline` のみです(`postal_code`や`address_ja`などは組み合わせが多すぎる、または数えにくいため対応していません)。また、以下の場合はエラーになりますので、設定を見直してください。

- 選べる値の種類が、作りたい件数より少ない(例: `boolean`は「true/false」の2種類しかないのに、5件分をuniqueにしようとした)
- 選べる値の組み合わせが200万通りを超える(範囲を絞ってください)
- `null_rate`(空欄を混ぜる設定)と同時に指定している

## 6. 困ったときは・現時点でできないこと

- **ふりがな(カタカナ)列**は現時点では未対応です(今後の検討事項)
- **1回の実行で複数の形式(例: CSVとJSONを同時に)を出力する機能**は未対応です。形式ごとに実行し直してください
- **複数のファイル(テーブル)をまたいだ整合性**(例: 注文データの顧客IDが、別ファイルの顧客一覧に実在するIDになっているようにする)には対応していません
- 設定ファイルの書き方を間違えると(例: `min`が`max`より大きい、日付の形式が違う、項目名が重複している等)、実行時にエラーメッセージが表示されて処理が止まります。メッセージの内容に沿って`schema.yaml`を見直してください

これらの制限や今後の拡張予定については、社内の検討資料([docs/requirements.md](requirements.md))にも整理されています。
